Modelagem de Dados

Os três níveis

Conceitual → DER, entidades, sem tecnologia
Lógico → tabelas e chaves, sem SGBD
Físico → tipos e índices, já no SGBD

Só o físico depende do SGBD. Tabela aparece no lógico.

DER: os símbolos

Retângulo = entidade · Elipse = atributo · Losango = relacionamento · Retângulo duplo = entidade fraca

Leia a frase: substantivo = entidade, característica = atributo, verbo = relacionamento.

Tipos de atributo

  • Simples: indivisível (CPF)
  • Composto: endereço → rua, nº, CEP
  • Multivalorado: vários telefones (proibido no relacional: vira tabela)
  • Derivado: idade (não se armazena)

Chaves

PK: única, nunca NULL
FK: aponta para PK de outra tabela, aceita NULL
Candidata: poderia ser PK · Alternativa: candidata não escolhida

Cardinalidade → tabela

TipoImplementação
1:1FK com UNIQUE em um dos lados
1:NFK no lado N
N:NTabela associativa com as 2 FKs

Leia sempre nos dois sentidos antes de decidir.

Normalização: o mantra

Cada campo depende da chave (1FN), da chave inteira (2FN) e de nada além da chave (3FN).

  • 1FN: valor atômico, sem grupo repetido
  • 2FN: sem dependência parcial
  • 3FN: sem dependência transitiva

Pegadinhas

  • 2FN só é violada com chave composta. PK de uma coluna + 1FN = já está em 2FN
  • PK não aceita NULL; FK aceita
  • Tabela associativa costuma ter atributos próprios (nota, quantidade), que são do relacionamento
  • Anomalias: inserção, atualização, exclusão

Banco de Dados SQL

As cinco famílias

SiglaComandos
DDLCREATE, ALTER, DROP, TRUNCATE
DMLINSERT, UPDATE, DELETE
DQLSELECT
DCLGRANT, REVOKE
TCLCOMMIT, ROLLBACK, SAVEPOINT

DELETE × TRUNCATE × DROP

  • DELETE: DML, linha a linha, aceita WHERE, dá ROLLBACK
  • TRUNCATE: DDL, esvazia tudo, sem WHERE, sem volta
  • DROP: apaga a tabela e a estrutura

Restrições e tipos

UNIQUE aceita 1 NULL; PRIMARY KEY não aceita nenhum.

CHAR = fixo · VARCHAR = variável
Dinheiro → DECIMAL (exato). Nunca FLOAT.

WHERE: operadores

BETWEEN 7 AND 9 inclui as pontas
IN ('Recife','Olinda') · LIKE 'A%'

% = vários caracteres · _ = exatamente um

NULL

WHERE col = NULL nunca funciona e não dá erro, simplesmente não retorna nada.

Certo: IS NULL / IS NOT NULL

COUNT(*) conta tudo · COUNT(col) ignora NULL

WHERE × HAVING

WHERE filtra LINHAS, antes de agrupar.
HAVING filtra GRUPOS, depois de agrupar.

Agregação (AVG, COUNT…) só no HAVING, nunca no WHERE.

Coluna do SELECT fora de agregação precisa estar no GROUP BY.

JOIN

INNER: só quem tem par nos dois lados
LEFT: todos da esquerda, com par ou não
CROSS: todas as combinações (JOIN sem ON)

Pergunta com "inclusive os que não têm" → LEFT JOIN.

Quem não tem par: LEFT JOIN … WHERE b.id IS NULL

Atravessar N:N = 2 JOINs.

Ordem lógica de execução

FROM → JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT

Por isso apelido do SELECT não vale no WHERE, mas vale no ORDER BY.

Sintaxe que a prova inverte

UPDATE tabela SET col = valor WHERE cond: SET sempre antes do WHERE.

Sem WHERE, UPDATE e DELETE valem para todas as linhas.

Subconsulta com vários valores → IN, não =.

Sistemas Operacionais

Processo × Thread

Processo = memória própria e isolada.
Thread = compartilha a memória do processo.

Thread tem só dela: pilha, registradores e contador de programa.

Estados do processo

Novo → Pronto → Executando → Bloqueado → Terminado

Bloqueado → Executando NÃO EXISTE. Quando a E/S termina, volta para Pronto.

Executando → Pronto = preempção.

Tipos de thread

  • Usuário: rápida; se uma bloqueia, todas bloqueiam
  • Kernel: paralelismo real, porém mais lenta (chamada de sistema)
  • Híbrida: combina as duas

Scheduler × Dispatcher

Scheduler escolhe quem executa.
Dispatcher faz a troca de contexto e entrega a CPU.

Fórmulas do escalonamento

Turnaround = conclusão − chegada
Espera = turnaround − execução

Resposta = 1ª execução − chegada. A prova quase sempre pede a média.

Passo a passo: desenhe o Gantt → anote conclusões → turnaround → espera → média.

SJF = menor tempo médio de espera (ótimo). Quantum grande demais → RR vira FCFS.

Deadlock: Coffman

Precisam das 4 ao mesmo tempo:

1. Exclusão mútua · 2. Posse e espera · 3. Não preempção · 4. Espera circular

Estratégias: prevenção (impede uma condição) · evitação = algoritmo do banqueiro · detecção · ignorar = avestruz

Deadlock × Starvation

Deadlock: ninguém do grupo anda, nunca.
Starvation: o sistema anda, só aquele processo nunca é escolhido.

Banqueiro é evitação, não prevenção.

Mutex × Semáforo

Mutex: binário, tem dono (só quem travou destrava), lock/unlock

Semáforo: contador, sem dono, deixa passar N, wait (P) / signal (V)

Semáforo iniciado em 1 = semáforo binário ≈ mutex.

Memória

Paginação = tamanho fixo → fragmentação interna
Segmentação = variável → fragmentação externa

Thrashing = mais tempo trocando página do que executando.
Substituição: FIFO (anomalia de Belady), LRU, Ótimo.

Disco e E/S

Pratos → trilhas → setores → cilindros. Setor = menor unidade física.

Interrupção = hardware · Trap = software (divisão por zero, syscall)

Polling (gasta CPU) < Interrupção < DMA (mínimo custo)

Segurança da Informação

Tripé CID

Confidencialidade: só quem pode, vê (vazamento)
Integridade: não foi alterado (boleto adulterado)
Disponibilidade: acessível quando preciso (DDoS, ransomware)

Extras: autenticidade (quem é) · não repúdio (não pode negar) · legalidade · privacidade

Ameaça × Vulnerabilidade

Vulnerabilidade = a fraqueza interna. Você conserta.
Ameaça = o agente externo. Você não controla.

Risco = probabilidade × impacto

Respostas ao risco: mitigar, transferir, aceitar, evitar.

Qual chave usar

SIGILO → pública do DESTINATÁRIO
ASSINAR → privada do AUTOR

Verificar assinatura → pública do autor. Abrir o que foi cifrado para você → sua privada.

Assinatura digital

Garante autenticidade + integridade + não repúdio.

NÃO garante confidencialidade: o documento continua legível. Pegadinha nº 1.

Certificado digital = a AC atestando de quem é a chave pública.

Autenticação e acesso

3 fatores: o que você sabe · tem · é. 2FA = tipos diferentes.

Autenticação (quem é) vem antes de autorização (o que pode).

DAC = dono decide · MAC = sistema por rótulos · RBAC = papel/cargo

Menor privilégio: só o acesso necessário.

Vírus × Worm × Trojan

Vírus precisa de hospedeiro e de execução.
Worm anda sozinho pela rede.
Trojan se disfarça e não se replica.

Ransomware → ataca disponibilidade, defesa real = backup.
Rootkit → esconde a invasão do SO.

Tipos de vírus

Executáveis · memória · boot (roda antes do SO) · driver · macro (Word/Excel) · código-fonte · polimórfico

Ataques

Phishing (isca falsa) · Engenharia social (manipula a pessoa) · DDoS (várias máquinas) · MITM · SQL Injection · XSS · força bruta · spoofing

SQL Injection se previne com prepared statements, não com antivírus.

Defesas

IDS detecta (passivo) · IPS detecta e bloqueia (ativo)

Backup 3-2-1: 3 cópias · 2 mídias · 1 fora do local

Incremental = desde o último backup qualquer. Diferencial = desde o último completo.

Hacker × Cracker e LGPD

A palavra que separa é autorização. Hacker = white hat; cracker = black hat.

Nenhum SO é imune. Alternativa com "imune" ou "sem vulnerabilidade" está errada.

LGPD, dado sensível: raça, religião, opinião política, saúde, biometria, vida sexual.
